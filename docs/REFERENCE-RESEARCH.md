# RUAGENTIC directory content

Website copy for ruagentic.com, followed by implementation notes and a source-based feature matrix. The publishing offer is US$49.99 once per listing or free publication after the project's Agentic JSON, TXT, and README pass the ruagentic.org publication audit.

## About

### Find the right connection for your agents

RUAGENTIC is a directory of MCP servers, clients, and tools for AI agents. Explore projects by what they do, open their documentation, and find the published connection details you need to get started.

Listings bring together information from public registries, project websites, repositories, and submissions. Sources are identified so you can distinguish imported information from details supplied by a project's publisher.

RUAGENTIC is part of the Agentic project. [ruagentic.org](https://ruagentic.org) provides the open file convention, generator, auditor, documentation, and developer tools. [ruagentic.com](https://ruagentic.com) helps people discover projects and publish directory listings.

You can publish a listing with a one-time payment or qualify for free publication by publishing Agentic files that pass the publication audit.

**Primary action:** Explore the directory

**Secondary action:** Add your project

### About our information

Imported information comes from the source linked on the listing. Submitted information is supplied through a RUAGENTIC account. A source label identifies where information came from; it does not establish ownership, endorsement, or independent testing.

An Agentic file check applies to the public files and checks recorded in its report. Follow the project's current documentation for installation, supported clients, authentication, and service behavior.

## Submission guidelines

### Help people understand your project

We welcome MCP servers, MCP clients, and tools for AI agents with public project information.

1. **Use the project's real name.** Add a short description of what it does and one or two concrete uses.
2. **Choose the right type.** Identify whether the project is a server, client, or another agent tool. A product can offer more than one server; explain the relationship in its description.
3. **Provide a public source.** Include your homepage, repository, or documentation. Add the actual server endpoint when your project offers one.
4. **Describe access accurately.** For MCP servers, include the supported transport and published authentication requirements. If you do not know a requirement, leave it unspecified rather than guessing.
5. **Link to setup instructions.** Explain installation or connection steps in your own documentation. Include relevant product pricing or account requirements when available.
6. **Keep credentials private.** Submit public URLs and parameter names. Never include API keys, passwords, private tokens, or URLs containing login credentials.
7. **Respect project ownership.** Manage projects you maintain or have permission to represent. If a project is already listed, request a correction rather than creating a duplicate.
8. **Keep claims factual.** Describe supported capabilities. Do not use another project's name, identity, usage figures, or endorsements as your own.

For free publication, the Agentic files must describe the project being submitted. Another website's passing report does not qualify your listing.

## FAQ

### What can I find on RUAGENTIC?

MCP servers, clients, and tools for AI agents. Each listing includes available project information and links to its sources or documentation.

### How are ruagentic.com and ruagentic.org related?

They are parts of the Agentic project. ruagentic.org provides the file convention and free tools for generation, validation, and auditing. ruagentic.com is the directory for discovering projects and publishing listings.

### Do I need Agentic files to get listed?

Agentic files are required for the free publication option. You can also publish through the US$49.99 one-time payment option.

### What does the free option require?

Your project's `agentic.json`, matching `agentic.txt`, and public `README.md` must pass the ruagentic.org publication audit. Complete your listing details and run the check during submission. A partial result still needs fixes before it qualifies.

### Where do I get the files?

Start at [the Agentic generator](https://ruagentic.org/generate/). Review the generated information, publish the files for your project, and use [the auditor](https://ruagentic.org/audit/) to identify any fixes. Merge useful README sections into your existing documentation.

### Can my README stay on GitHub?

Yes. Supply its public raw Markdown URL when it is hosted somewhere other than beside `agentic.json`. A GitHub repository page is an HTML page; use the README's Raw URL.

### Does a passing audit mean the service is safe or fully compatible?

It means the reported file and documentation checks passed at the recorded time. The publication audit does not run your tools, verify every statement, test every client, or certify a service's security, ownership, uptime, or recovery behavior.

### Does paying produce a verified badge?

No. Payment establishes listing eligibility. Any displayed check describes the evidence behind that check; a payment is not technical evidence.

### Why is a project listed if its publisher has not submitted it?

The directory also includes information imported from public registries and project sources. Imported entries identify their source. Their presence does not mean the publisher has registered with RUAGENTIC, paid for a listing, or adopted Agentic.

### Are imported details guaranteed to be current?

No. Project information can change after it is collected. Check the listed source and the project's current documentation before connecting or installing anything.

### Will RUAGENTIC host or run my MCP server?

Directory publication provides a listing and links to your project. Your service continues to run on your chosen infrastructure. Importing a URL does not install a package or execute its tools.

### Does a listing work with every MCP client?

Client support depends on the project's transport, authentication, and required protocol features. Use the project's setup instructions and your client's documentation to check compatibility.

### Is the listing fee a subscription?

No. The paid publication option is US$49.99 once per listing.

### My payment completed, but I do not see a listing. What should I do?

Return to your account and open the saved submission. Payment confirmation and publication are separate steps. If the status does not update, ask for help with the submission reference and payment receipt reference. Do not share card details or account credentials.

### How do I report incorrect information?

Use Help with the listing URL, the information to correct, and a public source supporting the correction. For project ownership or account access questions, include the relevant listing or submission reference.

## Help

### Get your listing published

Start with a public project URL, review the imported information, and complete the required details. Then choose the one-time payment or the free Agentic check and review your listing before publication.

| Problem | What to do |
| --- | --- |
| Import could not read the URL | Use a public HTTPS homepage or documentation URL. Check that it opens without login. You can still enter project details manually. |
| The server endpoint has no description | Add a homepage or documentation link and describe what the server does. A connection URL alone may not provide readable metadata. |
| JSON file missing or invalid | Generate or correct `agentic.json`, publish it at the reported URL, and run the audit again. |
| TXT does not match JSON | Regenerate `agentic.txt` from the current JSON and exact publication URL, then publish the matching pair. |
| README missing | Publish `README.md` beside the profile, or provide a public raw Markdown URL. |
| README URL returns HTML | Use a raw file URL. For GitHub, open the README and choose Raw. |
| README links point to another profile | Correct the links to your published `agentic.json` and `agentic.txt`, including their exact location. |
| Project references are missing | Add the Agentic convention and RUAGENTIC directory references described in the audit report. |
| Audit could not reach a file | Restore public access, check the final HTTPS URL, and retry. A network error does not prove that your service is broken. |
| Payment is pending | Wait for payment confirmation and reopen the saved submission. Avoid starting another payment for the same listing. |
| Confirmation email is missing | Check your account and spam folder. A published listing remains accessible through its URL even if the email is delayed. |
| An existing listing is incorrect | Include its URL and a public source showing the correction when asking for help. |

**Support form introduction:** Include the listing or submission reference and a short description of the issue. Public documentation links and the audit report's check ID help us investigate. Do not send passwords, API keys, card numbers, or private access links.

## Data labels and implementation alignment

This section is implementation guidance, not additional website promises.

| Label | Meaning and required evidence |
| --- | --- |
| Imported from [source] | Factual metadata was imported from that linked source. Keep its retrieval timestamp. |
| Submitted details | Information was supplied through a directory account. This alone does not verify project ownership. |
| Publisher-provided | Use for details supplied by the project's publisher; disclose the source and keep identity verification separate. If that relationship has not been established, use Submitted details. |
| Agentic files checked | The relevant publication audit passed. Link its report or show the check scope and date. |
| MCP Registry record | Link the actual record and observed version. A package keyword or `mcpName` alone is insufficient. |
| Authentication not specified | The available source did not establish an authentication requirement. Do not replace this with No authentication required. |

Keep working information separate from the published snapshot. Render email, payment, and audit messages only when their server-recorded states support them. Enable account editing or ownership-claim language only where those actions are implemented. Connect Help to the real support destination; no support email address is invented here. No refund, response-time, search-position, traffic, or lifetime-availability guarantee is supplied by this copy.
